# Model metrics: Phase 5 (deep learning)

Generated by `python -m models.report_phase5` from `models/results_phase5.json`; do not edit by hand. Independent checks: `python -m models.verify_deep`. Walkthrough: `notebooks/05_deep.ipynb`. Phase 4 baselines: `docs/MODEL_METRICS.md`.

**Data:** NASA C-MAPSS FD001, the same 100 test engines as Phase 4, each scored once at its last observed cycle. **Protocol:** settings chosen on 20 validation engines (stages A, B); 5 seeds refit on all 100 training engines for the validated epoch count; test set scored once at each engine's last observed cycle; true RUL capped at 125.

**Environment:** Windows, Python 3.14.7, PyTorch 2.14.1+cpu, 1 CPU thread, deterministic algorithms on. Total run time 74 minutes.

## Inputs and training

- **Windows:** the last W cycles of the 14 scaled sensors, ending at the current cycle; left, copies of the engine's first reading when fewer than W readings exist.
- **Training:** Adam, MSE on RUL/125, batch 256, up to 60 epochs with early stopping (patience 8) on the validation RMSE; the refit on all 100 training engines uses each seed's validated epoch count.

## Verdict

Rule: deep model wins only if its paired RMSE gap vs XGBoost is significant after Holm AND its near-failure MAE (true RUL <= 50) is not worse than XGBoost's.

**XGBoost remains the published model.** LSTM's RMSE gap vs XGBoost is -1.78 (95% interval -4.54 to +0.57, Holm p 1.000), not significant, and its near-failure MAE is 3.1 vs XGBoost's 4.4 cycles.

## Reproducibility

- **Same OS and PyTorch version as the published run:** `python -m models.verify_deep` re-trains seed 0 and requires identical test predictions and identical MC passes (difference exactly 0).
- **Other OS (CI runs Linux):** floating-point kernels differ, so one re-trained seed's test RMSE must lie within 4 x 0.34 x sqrt(1 + 1/5) = **1.49** of the published 5-seed mean (13.53). With the published seed sd, a correct re-run falls outside this band by chance with probability well under 0.1%.
- **Input bugs are caught exactly, on any OS.** The verifier rebuilds every training and test window from the raw files with independent plain-Python code and requires a value-by-value match; it also checks that seed 0 is refit for the epoch count found by the validation search. The band above is loose, so it is only relied on for broken training.
- **Every deliberate bug is caught by at least one of these checks.** Measured by `python -m models.tolerance_phase5` on the validation engines (the test set is not used): the correct model scores 10.10.
