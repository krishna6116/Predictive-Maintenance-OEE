# Model metrics: Phase 5b (FD003 confirmation and interval calibration)

Generated by `python -m models.report_phase5b` from `models/results_phase5b.json`; do not edit by hand. Independent checks: `python -m models.verify_fd003`. FD001 results: `docs/MODEL_METRICS.md`, `docs/MODEL_METRICS_PHASE5.md`.

## Why this phase

Phase 5 left three weak spots: 100 FD001 test engines could not separate the LSTM from XGBoost; everything was tested on one fault mode; and the 90% intervals covered only 82% of test engines. FD001's test set had already been seen, so fixing anything and re-scoring it there would be tuning to the test set. This phase uses NASA's **FD003** (100 new test engines, a second fault mode) as a fresh confirmation set, with every choice fixed in advance.

2. **Frozen recipe** (`models/run_fd003.py`): the 14 sensors, 168 features, RUL cap 125, XGBoost depth 5, LSTM (window 40, hidden 64, dropout 0.1, learning rate 0.003) and CNN (window 40, hidden 64, dropout 0.1, learning rate 0.001). Learned on FD003's own 20 validation engines by the same procedures: scaler (training engines only), tree and epoch counts (early stopping), Ridge penalty, interval scale factors.
3. **Pre-registered tests H1-H8** in one Holm family, and the verdict rule.

**Environment:** Windows, Python 3.14.7, PyTorch 2.14.1+cpu, XGBoost 3.4.1, 1 CPU thread. Run time 39 minutes.

## Verdict

Rule: LSTM replaces XGBoost only if H1 is significant after Holm with LSTM better AND its pooled near-failure MAE is not worse.

**The LSTM replaces XGBoost as the published model.** Pooled over 200 engines its RMSE gap is -2.31 (95% interval -4.05 to -0.76, Holm p 0.007) and its near-failure MAE is 2.76 vs 4.60 cycles.
