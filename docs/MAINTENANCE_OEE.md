> **Simulation, not measured results.** NASA C-MAPSS is simulated engine data with no production records. The plant, its output, downtime and OEE below are a documented simulation. The forecasts are real model outputs; everything after them is simulated.

**Run ID:** `phase6-618b9fbc3b7b` (a hash of the inputs and settings; the same inputs give the same ID, so database writes replace rather than duplicate). **Environment:** OR-Tools 9.15.6755, 1 solver worker, seed 0.

## Pipeline

Forecast (published LSTM + rule-E 90% interval) -> alert on the lower bound -> CP-SAT schedule under crew limits -> simulated plant -> OEE. Forecasts come from the published seed-0 LSTM of each dataset (LSTM-FD001-seed0-W40-h64-do0.1-lr0.003, LSTM-FD003-seed0-W40-h64-do0.1-lr0.003). Forecasts at every observed test cycle were produced by rebuilding that model (`python -m maintenance.forecasts`), which first reproduces the published last-cycle predictions and all MC passes exactly.

## Settings and assumptions

| Setting | Value | Source |
| --- | --- | --- |
| Alert | lower 90% bound <= 20 cycles; critical <= 5, high <= 10, medium <= 20 | guide |
| Schedule | 7 days, 3 crews a day, 2 cycles a day | guide |
| Schedule cost | 100 per late cycle, 1 per early cycle, 1000 per unserved engine | guide |
| Plant | 8 h per cycle, 10 units/h, service 8 h, failure 48 h | guide |
| Degradation | last 20 cycles: speed -10%, scrap 5% (otherwise 1%) | guide |
| Fixed interval | N = 10th percentile of training lifetimes: FD001 154, FD003 166 cycles | guide, data |
| Renewal | A service or a repair ends the machine's current engine life (the engine is replaced or overhauled to new). OEE is totalled over each machine's single life; by the renewal-reward theorem the fleet ratio equals the long-run ratio if lives repeat. | assumption (guide silent) |
| Calendar | All machines start at cycle 1 on day 0 and run CYCLES_PER_DAY cycles a day (the Phase 2 replay convention). A machine fails when it completes cycle L (its true failure point, RUL 0). It runs degraded (speed loss, more scrap) in its last 20 cycles, i.e. while its TRUE remaining life is < 20. | assumption (guide silent) |
| Service timing | A service booked for day d happens at the start of day d, before that day's cycles run. | assumption (guide silent) |
| After data ends | NASA test files stop before failure. After a machine's last reading the predictive policy has no new data, so it keeps using its last forecast, aged by one cycle per cycle run. | assumption (guide silent) |
| Crew limit | Only the predictive policy is crew-limited (as in the guide). Run-to-failure and fixed-interval services are not, which favours the two baselines. | assumption (guide silent) |
| Work orders | A booked service is kept (no re-planning of booked orders). An engine with an open order is not re-booked. If it fails before its service day, that is an unplanned failure and the order is cancelled. Flagged engines left unserved are retried the next day. | assumption (guide silent) |
| Rounding | rul_low is floored to whole cycles before scheduling (the guide's int()); flooring is conservative. | assumption (guide silent) |

**Why the predictive policy still has 8 failures:** all 8 happen after the machine's NASA test data has ended, so the planner was working from its last forecast, aged cycle by cycle. In 8 of them the lower bound at the last reading was already above the true remaining life (an interval miss, which a 90% interval allows about one time in ten). With live data, new readings would keep correcting the forecast; here they cannot, so this is a limitation of the truncated test files, not something fixed by tuning.

## Limitations

- The plant, production, downtime and OEE are simulated with the guide's assumptions; no real plant data is used.
- NASA test files stop before failure, so the predictive policy has no new readings late in each machine's life.
- One life per machine (renewal accounting); spare parts, travel time and crew skills are not modelled.
- Fixed-interval and run-to-failure services are not crew-limited, which favours them.
- Bootstrap intervals treat machine outcomes as independent although the predictive policy's machines share crews.
